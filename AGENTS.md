# REX — for agents and contributors

Terminal sidecar with a pixel-art dinosaur. Mascot on the left, what the agent is doing on the right. Watch-only, plus one thing it hands over: it does not run, approve or steer the agent; it adds the explicitly pinned task to each prompt as context (docs/ux.md §7a).

`rex start` works from any directory. The feed is `~/.rex/session.jsonl` (override with `REX_EVENTS`).

Install and user docs live in `README.md`. This file is how to change the code.

## Do not

- Add palettes or a `--color` flag. Yellow from `assets/idle.png` is the only look. (On Terminal.app without truecolor the *same* palette is quantized to xterm-256 — `mascot.DetectDepth`; that is not a second palette.)
- Add dependencies, frameworks, or a config system without a concrete need. Go 1.22+ stdlib plus `golang.org/x/sys` and `golang.org/x/term` for the TTY.
- Scrape transcripts or use the Cursor SDK to watch the in-IDE agent. Hooks only.
- Steer, inject prompts, or auto-approve tools unless the human asked for that this turn. Hooks write stdout only to hand the agent the explicitly pinned task (or a new plan with no tasks yet), on the events and in the shapes of docs/ux.md §7a, capped at 1,500 bytes and bound by a 750 ms deadline; never anything else, never a prompt, never an approval (Cursor's prompt reply carries `"continue": true` only because Cursor's docs don't mark that field optional, and never `false`; docs/ux.md §7a has the merge caveat). The plan file stays the source of truth: the `rex-plan` skill still has the agent re-read it every turn.
- Give Rex actions on a plan again (pin, done, send-off, brief, typed notes, a clipboard), or make the human copy anything from Rex into an agent. The agent drives the plan; Rex only shows it.
- Invent a custom `.rex` language. Plan files are JSON named `<name>.rex.json` under `rex/plans/` (commit that folder). Do not load them into the agent this turn. Don't `go build -o rex` at the repo root — that path is the plans directory.
- Dump Write bodies, duplicate thoughts, or flatten a reply's or prompt's markdown into one blob in the pane (a thought run's one-row preview of its latest thought is by design, docs/ux.md §10).
- Giant ASCII, extra emoji, or a web UI squeezed into the terminal.
- Wire a harness without an explicit `rex ingest --install <name>`. Wired today: Cursor (the install script does it), and opt-in Claude Code, Codex and OpenCode (a generated `plugins/rex.js` that pipes events to `rex ingest --source opencode` and asks it for the pin note before each prompt, sends allow-listed fields only (no file bodies, diffs, attachments or tool output), skips a subagent's prompts, replies, thoughts, errors and turn ends (its tool calls still show), sends the turn's last text with its idle, never throws, and waits at most 1.5 s, only in `chat.message`, for the pin note, which it pushes onto the prompt's parts as one synthetic text part; its first line carries its version, `plugin v2`). Codex's `hooks.json` may only hold `description` and `hooks`, and Codex trusts a hook by a hash of its handler, so the entry must stay byte-stable; the user trusts it once in Codex's `/hooks`.
- Add plan fields beyond [docs/plan-format.md](docs/plan-format.md) v1 or extra mascot poses unless asked this turn. `internal/plan` parses plans leniently (Problems, not errors); keep it that way.

Idle and future poses are **40×40**. Ctrl+C twice to quit. Respect `NO_COLOR`. macOS, Linux, and Windows 10+ (VT).

## Mascot

Keep rendering separate from watch/TUI logic.

To change idle: replace `assets/idle.png`, then:

```bash
go run ./cmd/importsprite --apply assets/idle.png
```

That writes the idle `Pixels(...)` grid into `internal/mascot/sprites.go` and the sampled RGB values into the yellow palette, 1:1; restart `rex start` after it. The grid's letters are palette roles; the current idle grid uses these (the full set, with eye, white, mark, green, red and teal, is `mascot.PixelRoles`):

| Letter | Role | Letter | Role |
| --- | --- | --- | --- |
| `k` | outline | `n` | mid |
| `y` | body | `a` | accent |
| `Y` | highlight | `b` | belly |
| `o` | shade | `p` | blush |
| `d` | dark | `s` | shadow |

**Leave blink, glance, and squat as transforms** on `IdleRows` (`PaintPixels` / `ShiftBody`). Do not hand-edit a second grid that drifts from the PNG.

Blink drops the top eye pixel (the face `k` at column 25, rows 13–14 on the current sprite). Squat is `ShiftBody(..., dy=1, keepBottom=7)` so the shadow stays planted.

Breakdance is the 40×40 sheet `assets/breakdance.png` (left-to-right, top-to-bottom). Type `/breakdance` in the plan list's composer to play it **once**, then resume the turn pose. When a plan opens (start's, an attach, a pick or a create in the plan list, an offer taken with `o`; `openedPlan`), the mascot **glances once**: the glance transform (`mascot.Glance`) for `glanceTicks` frame ticks over whatever pose plays, whose own frames keep their clock under it; never on a reload of the open plan, never over a breakdance, and only where the mascot shows (`app.glanceOnce`). Typing is `assets/typing.png`. Hook `user` / `thought` → thinking; shell / tools → running; `text` / `idle` (turn end) → idle; `error` → idle, except a failed tool call (meta `tool`), which keeps the turn running. Thinking and running play **typing**; idle is only when nothing is in flight. Rex's own lines never start or end a turn. Map sheet pixels onto the yellow palette — do not blit the PNG. Do not dump Write bodies.

If the README hero should match, rebuild `assets/rex.png` from `idle.png` with nearest-neighbor scale.

Animation must stay slow. Never let it eat input or overwrite the log. The live loop never clears the screen per frame: `renderer` repaints only changed rows (each erased from column 1, then written whole and reset, never erased after the write, since that would wipe the last column; inside DEC 2026 sync, cursor hidden while painting) and does a full repaint only on the first frame, resize, Ctrl+L and SIGCONT. `TERM=dumb` gets the static card without color. Rendered mascot rows and the AGENT layout are cached, and so are the plan list's plan summaries.

Unix live mode is cbreak (ECHO/ICANON/ISIG/IEXTEN off, IXON off so Ctrl+S can't freeze output) and **must keep OPOST**. Do not use `term.MakeRaw`. On Unix, input goes through `keyDecoder`: whole escape sequences, whole UTF-8 runes, Alt chords dropped (never Esc plus a key), bracketed paste as one token that never submits, even when it stalls. On Windows, `consoleKeys` maps key records (Esc, surrogate pairs), a burst with text after a newline (or 16+ characters) becomes one paste on a best-effort basis, bracketed paste stays off (the console has no markers), and `ENABLE_PROCESSED_INPUT` / VT input are cleared so Ctrl+C is a key. Keys from one read are applied one at a time (`app.keys`); the mascot ticks on the clock, not on empty reads. SIGTERM/SIGHUP/interrupt leave through the same restore path as Ctrl+C twice.

## Watch feed

Cursor hooks (`~/.cursor/hooks.json`: `sessionStart`, `beforeSubmitPrompt`, `afterAgentThought`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `afterFileEdit`, `afterAgentResponse`, `stop`; `sessionStart` records nothing, it only hands a new chat the pin) spawn `rex ingest --source cursor`; Claude Code hooks (`~/.claude/settings.json`, or the repo's git-excluded `.claude/settings.local.json` with `--project`) spawn `rex ingest --source claude`; Codex hooks (`$CODEX_HOME/hooks.json`, default `~/.codex`) spawn `rex ingest --source codex`; OpenCode's generated plugin (`$XDG_CONFIG_HOME/opencode/plugins/rex.js`, default `~/.config/opencode`) spawns `rex ingest --source opencode`, sends a turn's reply with its `session.idle`, and asks for the pin note before each prompt. Adapters map vendor JSON to `watch.Event`; `AppendEvent` dedupes (never two events whose `tool_use_id`s differ: those are two tool calls) and only ever appends (a growing reply is a new line; `ExtendLog` merges it); `NewEventTail(path, true)` paints new lines, and on start `warmStart` paints the last ~20 events of this repo under `── before rex started ──` (restoring the turn only if the newest is under 2 minutes old). Ingest stamps `meta.cwd` / `roots` / `session` / `tool_use_id` from the payload (never the hook's own cwd); `watch.Scope` decides whether an event is this repo's from its cwd or roots (its file only when it has neither) and shows tool paths repo-relative; the TUI hides other repos' events (counted under Help), keeps events with no known origin, and drops feed lines that claim to be Rex's own blocks.

`rex ingest` runs inside agent hooks: run from a hook it **always exits 0, never exits 2, and writes stdout only the pin note, once** (harnesses read exit 2 as "block" and some feed stdout to the agent); besides that note, only `-h`, `--version` and the interactive `--install*` / `--uninstall` flags print, and only those can exit non-zero (1, never 2). An unknown top-level command exits 1, never 2. Stdin reads and the feed lock are time-bounded. The feed is private (file 0600, `~/.rex` 0700, tightened on old installs). Keep it that way. Visible assistant replies come from `afterAgentResponse`, which Cursor currently fires with the **final** message of the turn. In-between chat lines are not on any hook — do not scrape transcripts to invent them. Thoughts still arrive via `afterAgentThought`. Do not map Cursor's `stop` as text. Claude Code's `Stop` carries `last_assistant_message`, the turn's final reply: that one is text. Claude hook payloads that carry `cursor_version` are Cursor running Claude's hooks and are dropped (Cursor's own hooks already report them).

The pin note (docs/ux.md §7a): on an explicit `--source claude` or `--source codex` hook's `UserPromptSubmit`, or its `SessionStart` with `source: "compact"`, never for a payload with `cursor_version`, on an explicit `--source cursor` hook's `beforeSubmitPrompt` and `sessionStart`, and on the OpenCode plugin's `{"type":"context"}` request to an explicit `--source opencode` (sent from `chat.message` for a root session's prompt with text of the person's), and never for a subagent (`agent_id`) (`watch.ContextEvent`), ingest reads the payload once, looks up the pin by 750 ms from the process's start (`plan.PinFor`: the repo from the payload's `cwd`, or for Cursor, whose user hooks run in `~/.cursor`, from the first of its `workspace_roots`, then `$CURSOR_PROJECT_DIR`, that is in a git repo, else the first of them (`watch.ContextFolders`, `plan.PinFolder`; OpenCode's request names its project's directory as `cwd`), never the hook's own folder; only `state.json`'s last plan there, through the path jail, so what the human sees in Rex is what the agent gets and a committed plan Rex never opened sends nothing; that plan's `active` leaf is sent, or, with no tasks yet, the plan is named; tasks and no pin, a read-only plan, one it can't read, or a path the note would fold or cut send nothing), words it (`plan.PinNote`: facts, `Rex note` first, cleaned, `system-reminder` defused, 1,500 bytes at most), shapes it (`watch.ContextReply`: one JSON object for Claude Code, plain text for Codex, one JSON object for OpenCode's request (`{"note":…,"pin":…,"pin_plan":…}`: the task's id and the plan's path as the file spells them, left out where they would take the reply past the plugin's 8 KB), one JSON object with every non-ASCII character escaped as `\uXXXX` for Cursor: `{"continue":true,"additional_context":…}` on a prompt (`continue` is the one field Cursor's docs don't mark optional there and was in every reply seen adding the context; Cursor doesn't document whether a later `true` undoes another hook's `false`, so docs/ux.md §7a, README and SECURITY say a prompt-blocking hook in an Enterprise, Team or project `hooks.json`, or one placed ahead of Rex's entry, must not count on outlasting Rex's reply), `{"additional_context":…}` on `sessionStart`, never `"continue": false` or `user_message`; a session start's pin note says it is as of the start of the session, and a new plan's line is the same line then), records the event with `meta.pin` and `meta.pin_plan` only when it prints (`AppendEvent` never dedupes a prompt into one that carried another pin), and writes stdout once at the end. OpenCode's request is never recorded: the plugin (`opencodePluginJS`) waits for the reply at most 1.5 s, reads at most 8 KB, parses it and catches everything, pushes the trimmed note onto `output.parts` in place as one `synthetic: true` text part whose id sorts after the prompt's own, and, only when it added the note, copies the reply's `pin` and `pin_plan` into the prompt's `chat.message` payload; the run that records the prompt stamps them as `meta.pin` and `meta.pin_plan` (`watch.SentPin`, an explicit `--source opencode` only) with no second lookup, so the event names what the note it carried named, never read back from the note's wording (a task id may hold ` · `, and the note cleans and cuts what it names). `MapOpenCode` never takes them from the payload. Every other event and harness prints nothing; a missed deadline or a crash prints nothing and still records the event. Claude Code's handler and Codex's `hooks.json` did not change for it (Codex trusts a hook by its hash); OpenCode's plugin did, so its marker line carries a version (`// generated by rex · plugin v2 — safe to delete`): `--install opencode` replaces an older one and keeps a newer Rex's (it says so; an unversioned marker is v1, which never asks for the note: `Harness.Old` tells it apart, though feed health doesn't show it yet; a plugin change OpenCode users should get bumps `opencodeVersion`), and OpenCode loads it on its next start; Cursor's `hooks.json` gained `sessionStart` (`CursorHookEvents`), which `--install cursor` splices in on a rerun and `--uninstall cursor` takes out. Rex's `sessionStart` and `beforeSubmitPrompt` entries go first in their lists (`cursorFirstEvents`, `jsonedit` `Prepend`; an install moves an older one there), so the person's own hooks in that file answer after Rex's: Cursor keeps the last answer for fields it doesn't merge, which may include `continue` and `additional_context`. Cursor's `beforeSubmitPrompt` `additional_context` is undocumented (seen read by Cursor 3.20 and its CLI 2026.10, ignored by 3.2); `sessionStart`'s is documented but is added once a chat, frozen at its start.

New harness = adapter + a `Harness` registered in `internal/watch/harness.go` (Present / Wired / Install / Uninstall, and Old when an older install can't hand over the pin). Installing happens only on an explicit `rex ingest --install <name|auto>`; `--uninstall <name>` takes Rex's entries back out and leaves everything else. Do not special-case vendors in `live.go`. Tests run with HOME pointed at a temp dir (a `TestMain` in each package that touches HOME: `cli`, `plan`, `skill`, `tui`, `watch`), with `REX_EVENTS` unset (and, in `cli` and `watch`, `CURSOR_PROJECT_DIR`, which Cursor's pin lookup reads). Installers edit the harness's config through `watch.UpdateJSONFile` + `internal/jsonedit`: splice only what Rex owns, keep every other byte, refuse a file that does not parse, keep a `.bak`, write atomically. Never round-trip a user's config through a `map`.

Kinds: `thought`, `text`, `user`, `command`, `question`, `result`, `idle`, `error`. Rex's own local kinds, `plan`, `drift` and `before` (source `rex`), never come from the feed.

## Plan files

`internal/plan` reads the v1 format in `docs/plan-format.md`. **Rex never writes a plan**, except the new empty v1 stub the human creates in the plan list (`+ Create 'x'`, the Name prompt), which never overwrites a file. The agent writes everything else, statuses and completion fields included, as `internal/skill/rex-plan/SKILL.md` teaches: it sets a task `active` to start it and `done` with `accomplished`, `modified`, `verified_how` and `completed_notes` to finish it, and Rex reloads and shows it. Never marshal a plan out of a struct or a `map` over a file that exists. What Rex remembers between runs (the last plan per repo) goes in `~/.rex/state.json`, never in the repo; an old file's `pins` are ignored. Rex reads the optional stack fields `base` and `branch` (docs/plan-format.md, Stacks) and reports bad ones as Problems; agents write them and work out where a stacked PR goes from the file. Rex never runs git.

## TUI

The target loop, key map and screen states are in `docs/ux.md`. TUI changes cite the section they implement.

- Left 40 columns: the mascot, only from 110 columns and 16 rows (`TextOnlyBelow`, `textOnlyRows`: a 68-cell text column at 110), cropped from the bottom under 20 rows; narrower or shorter terminals are text-only, the text from column 0 (all 80 cells at 80 columns), and under 24 text columns Rex shows `widen to 24 columns` (no `REX` wordmark anywhere) and ignores every key but Ctrl+C and Ctrl+L; under 7 rows nothing edits or submits the plan list's hidden draft, and its footer drops `type to …`, `enter` while the hidden draft has text or a Name prompt is open, and `? help` while the hidden draft has text (`withoutEnter`); see `layoutFor`). The text column is used up to 100 cells (`maxText`); wider, the rest of each row stays empty. Right: the screen's text. On AGENT, the block grammar (docs/ux.md §10, `stream.go`): each block is named by its first characters and only two have a rule, `reply ───` and `── before rex started ──`. A run of thoughts is one row, `thinking ×N  <latest>` (`thinking  <text>` for one), and the newest block, when it is a thought run, goes on over a second row while the turn is in flight (`viewOpt.live`: thinking or running, scrolled or not, so neither a hidden tool call nor scrolling changes the layout; a drawn block or the turn's end settles it; not under 12 rows, `blankFrom`); under 30 cells it is just `thinking ×N`. A command run is one clipped `$` row each, over 5 `$ … +N earlier` then the last 4; a failed tool call is one `✗ <what> · <why>` row (what clips first, a path from the left, at `/` or the OS separator; `watch.FailParts` reads the adapters' line back, `watch.TurnErrorText` the turn's error); the turn's own error `✗ error · …` takes up to 3; a question is an `[ASK]` pill; Rex's own lines are `rex › plan · …` and `rex › drift · <pin>` (never from or to the feed). Blank rows go only around prompts and before replies and asks, and none under 12 rows (`viewOpt.tall`). The fold is display only: the feed keeps every thought, Help says so, and no key unfolds a run. Replies bright, commands and thoughts muted; hard drift is the pin's yellow, soft drift muted, and only an error red. Skip file-look commands and `done`/result echoes. Each assistant `text` event is its own reply block. The view cache is keyed by (revision, width, live, tall), so a turn's end settles a live run with no new event; a scrolled view keeps its lines by the signed change in rows (measured on the layout before the batch, so a run that settles under it counts), never under 1, with what the 400-event cap trims above it left out. The empty tab (feed health) is a page: top-anchored, scrolled like Wait when it runs past (`pageKey`, `app.emptyScroll`: ↑↓, page, Home / End, `↑ more` / `↓ more`, and `↑↓ scroll` in its footer only then, `pageFooter`), its lead is row 1 (`feedLead`, `feedShort` where it doesn't fit), and its body starts at FEED.
- **Rows 0 and 1 and the footer are chrome on every screen, and from 12 rows row 2 and the notice row too** (docs/ux.md §4, `titleLine`, `statusRow`, `footerLine`, `app.context`, `app.noticeOf`). Row 0 is the title row from column 0: a breadcrumb (`Plans › cuj/`, `Send-off demo › card-highlight`, `Agent`; the current crumb a bright bold `title`, the ones before it and ` › ` muted) that is also the Esc ladder, the page's meta muted (the outline's `1/3 done · following`, short `1/3`; latched shows no word; `· read-only`; a red `· can't read`; a task's state, `pinned` in the pin's yellow), and three cells after it the places' label `plan · agent`, the place on screen bright `text` and the rest muted, which never changes with news (`placeLabel`). Fitting: the breadcrumb clips first, down to its current crumb; then the meta goes, its short form first; then the label shortens to the current place's word; under 30 text cells (`labelFrom`) it goes; only then is the current crumb cut. On the outline row 0 is the selectable title row: it keeps a 2-cell gutter selected or not and is fitted with it (`Page.Selectable`), so the cursor changes only the gutter (`❯`, the crumb and meta purple, the label keeping its roles). Row 1 is the context row, muted: the outline's pin line (`pinned  <id> · <title>`, the id yellow and the title text; `nothing pinned · next up <id> · <title>`, never yellow; `nothing pinned · nothing unblocked` / `· no tasks yet`; `✔ all tasks done`; its right side, the send state, is empty for now), a detail's `task 2 of 3 · under <parent>`, About's path, AGENT's turn (`thinking`, `running`, `idle`, `waiting on you` text, `turn error` red) with `pinned <id>` / `nothing pinned` on the right, the plan list's notice (outside git, an old `rex-plans/`, plans off) on every plan list screen and Wait, else each page's sentence. Row 2 is blank from 12 rows (`blankFrom`); 11 rows lay the outline, its details and the plan list's accordion out as 12 do (`planRows`, `ComposeOptions.PlanRows`, `listFit.short`), so a taller terminal never shows less. The notice row (H−2 from 12 rows; under 12 rows a notice takes row 1 while it shows) shows one message, the first that applies (`noticeOf`): an error (`✗ plan JSON error …`, the plan list's `✗ <Err>` until the next key, a failed open), both places; your agent asking or its turn's error (`app.needs`, memory only, `heard`), on PLAN: an ask until the turn goes on past it (as `lastKind` leaves `question`), a turn's error until the next prompt, either until you look at AGENT, and nothing raised while AGENT is on screen; a toast (4 s, `toastFor`), on PLAN, one raised while AGENT is on screen waiting for PLAN (`toastWait`); a new plan offered or held (`Your agent wrote <title> (<path>) · o opens it`, `· opens when the line is clear`), both places; hard drift (`off pin · …`, `off pin` yellow), on PLAN until the pin moves, an on-pin edit of that file, or you look at AGENT; read-only. There is no tab bar, cue or turn word on PLAN. The footer (`fitFooter`) is keys only: one muted line of `key verb` segments joined by ` · `, keys in words (`↑↓`, `enter`, `esc`, `tab`, `?`, `home`, `end`, `type to …`, `ctrl+c`; never `⏎` or `↔`), each only where its key acts; `enter` names where it goes and `esc` its target; segments drop by rank (`footerRank`: ? help last and never dropped, then enter, esc, tab, ↑↓, typing, `end live`, `home oldest`), the display order never changes, and each is fitted at its longest form on that screen (`seg`'s `Wide`), so moving the cursor never changes which segments show. After the first Ctrl+C it is `ctrl+c again to quit`, muted. A test pins each screen's footer at 24, 38, 60 and 79 cells.
- User prompts: no `YOU` rule. Invisible column, at most half the pane, **right-aligned as a box**, **left-aligned text inside**. Color `text`.
- Markdown → headings, lists, stripped emphasis, fenced code as `│ ` lines.
- **Start lands on a plan, not the plan list** (`attach.go`, docs/ux.md §11): the last plan opened in this repo (`~/.rex/state.json`), else the newest `rex/plans/**/*.rex.json`, else the **Wait** screen (`Plans › Waiting for a plan`, row 1 the plan list's notice or `Rex opens the plan your agent writes.`: `no plan yet · tell your agent to make one`, `HOW IT GOES`, the esc and tab keys, and `agents learn plans from the rex-plan skill · rex ingest --install-skill` while `skill.Look` finds the skill nowhere; `rex-plan skill is out of date · rex ingest --install-skill [--project]` while a copy is an older Rex's: an older `skill vN` in its marker, or none; one of this version, CRLF or not, or a newer Rex's is current, and `skill.Install` never replaces a newer one; on a short screen the blank rows, the keys, HOW IT GOES and the long hint go first, never the headline or the short hint, and what doesn't fit scrolls; paths break after a `/` and the command is never clipped). Either plan is *following*: a completed write (never a read, a failed write or a shell command) of an existing `*.rex.json` under this repo's `rex/plans/` by this repo's agent opens that plan's outline in PLAN, the one exception to "events never move you" (docs/ux.md §1). Plans are compared by file (`samePlan`, `os.SameFile`), never by spelling, and a write of the open plan never hides another plan written in the same batch. Text in the plan list's composer or a Name prompt (either place) holds the attach until it clears, and the notice row says `Your agent wrote <title> (<path>) · opens when the line is clear` (`· opens when the prompt closes` while a Name prompt is open, even an empty one); nothing else does (no other screen has a composer), and the place never changes. An attach leaves one muted `rex › plan · following <name>` line on AGENT. The loop applies a read's keys before the events polled with it (`app.step`). While no plan is open a poll also looks for the newest plan file; once one is open the folder is never scanned to change the screen. Picking another plan in the plan list (or creating one there) *latches* it (`latch`); nothing else does, and enter on the open plan (under `OPEN`) picks nothing new and keeps following. A write held while you pick or create a plan there becomes the offer (`offerHeld`), neither opened nor lost, unless it is the plan you picked. ## Code conventions

- Match the code around you. Comments are rare and say *why*. Names are short (`b` for a browser, `ev` for an event, `opt` for compose options).
- Tests go in a `*_test.go` file in the same package. Use `t.TempDir()` for any repo, plans dir or feed file, and never touch the real `~` or `~/.rex`. Assert on rendered text with `viewText(BuildLogView(...))` / `viewText(BuildPlanView(...))`, and use `NO_COLOR`-style `Enabled: false` frames when you need plain text.
- `LogLine.Kind` picks the color. It is looked up in `mascot.UI`, then in `kindColor`. A new UI role goes in `mascot.UI`, not in a new palette. A line with more than one style carries `Spans` (`style.go`): its `Text` stays their plain join, a span without a role takes the line's, and `paintSpans` cleans and clips them by cells like `clip`. Bold (`mascot.PaintStyle`) is the only attribute; no dim, reverse or underline. Yellow means only the pin, and hard drift, which is off the pin (and the mascot's own palette). Purple means only the selection, green only ✔, red only an error. No background fills (docs/ux.md §5): the selection is `❯` in the 2-cell gutter and purple text, on which the pin keeps its yellow and an error its red (`picked`); `✔` is green wherever it is drawn (`paintRun`); titles are the bright bold `title`, never yellow; `pickbg`, `folder` and `you` are retired, and the mascot's half-block pixels are the only background Rex paints. Color never changes the characters: a pill is `[WORD]` in both modes.
- Pane width math uses `cellLen` / `clip` / `padRight`, never `len()` or rune counts (`runeLen` is only for the draft cap).
- Whether a frame has the composer is `ComposeOptions.Composer`, set from `app.composing()`; drawing, the cursor and the footer read it, never their own guess. Likewise the screen decides PLAN's body: `ComposeOptions.Plans` is set only while the plan list is on screen; otherwise PLAN draws `PlanView` (Wait or the open plan's screen), even an empty one.
- Vendor names live in `internal/watch` (adapters, installers), in the `rex ingest` flags, `--source` list and help in `internal/cli`, and in `scripts/install.*`. Adding a harness touches all three. The TUI paints event kinds and never branches on a vendor.
- Keep stdout clean in `rex ingest`: the pin note on the events docs/ux.md §7a names, in one write, and nothing else. Hooks treat stdout as agent input, and exit code 2 as "block".

### Go 1.22 floor

`go.mod` says `go 1.22` and CI runs Go 1.22. Code built with a newer toolchain can still break the 1.22 floor:

- **The compiler** rejects newer language features, such as range-over-func, because `go.mod` sets `-lang`.
- **`go vet`** on Go 1.23+ flags any standard-library API newer than `go.mod` through its `stdversion` check. `go test` runs that check only on the newest toolchains (not on 1.23 or 1.24), so always run `go vet` explicitly, with a new toolchain. Examples it catches:
  - 1.23: `iter`, `maps.Keys/Values`, `slices.Collect/Sorted/Chunk`, `unique`
  - 1.24: `os.Root`, `t.Chdir`, `t.Context`, `b.Loop`, `strings.Lines/SplitSeq/FieldsSeq`, `bytes.Lines`
  - 1.25+: `testing/synctest`, `sync.WaitGroup.Go`, `t.Output`, `errors.AsType` (1.26), `encoding/json/v2` (1.27)
- **Nothing catches struct-tag options.** `json:",omitzero"` (1.24) compiles on 1.22 and is ignored there, so the same code writes different JSON depending on the toolchain. Don't use it. Rex writes the feed, `state.json` and new plan stubs as JSON.

`min`/`max`, `clear`, range over an int, and the 1.21 `slices`/`maps` functions are fine.

## Workflow

- **Branches.** Branch from `dev`. When a change depends on unmerged work, stack it: cut the branch from the previous one and open the PR against it. Name branches after the issue: `feature/task_completion`, `fix/key_input`, `docs/ux_spec`.
- **One branch, one issue.** Each branch closes exactly one issue. Work with no issue gets one first.
- **PR body.** Include the problem, what changed, why it is needed, how it works, the tests run (with output), terminal captures for TUI changes, and any existing behavior or test that changed on purpose. Stacked PRs say what they sit on: merge them bottom-up and don't squash.
- **Fixing a lower PR in a stack.** Add a commit to that branch, never amend. Then rebase everything above it and push each moved branch (`--update-refs` needs Git 2.38+):

```bash
git checkout <top-of-stack>
git rebase --update-refs <fixed-branch>   # moves every branch in between too
git push --force-with-lease origin <each moved branch>
```

- **Before opening a PR,** run the gate and a review pass. Save the gate as `gate.sh` at the repo root (git ignores it) and run it with `bash gate.sh <base-branch>` (don't paste it into your login shell: it stops at the first failure):

```bash
set -euo pipefail
base=${1:?usage: bash gate.sh <base-branch>}
out=$(gofmt -l .); [ -z "$out" ] || { echo "gofmt needed: $out"; exit 1; }
for os in darwin linux windows; do GOOS=$os go vet ./...; done
staticcheck ./...
go test -race ./...
GOTOOLCHAIN=local go1.22.12 test ./...      # go install golang.org/dl/go1.22.12@latest && go1.22.12 download
git diff --exit-code "$base" -- go.mod go.sum  # no new deps, no toolchain line
echo "gate ok"
```

  staticcheck: `go install honnef.co/go/tools/cmd/staticcheck@2026.2.2`.

- **Review pass.** Read-only reviewers, each with one job:
  - critique the design and how it interacts with the system;
  - drive the TUI in tmux on its own server (`tmux -L <name>`, never the default one), only when the UI changed;
  - try to break it and check for regressions;
  - lint and format;
  - a final readiness check after fixes.

  Fix each finding, or say in the PR why it was skipped.

- Follows this file and any PNG the human attached.
- The pre-PR gate in Workflow passes.
- Terminal state restores on quit / Ctrl+C.
- No speculative product, extra commands, or architecture for a feature that was not requested.
